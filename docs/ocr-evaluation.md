# OCR 测试口径

## 两类验证必须分开

人工夹具验证回答“识别文本进入 ParserAdapter 后，字段转换是否正确”。它不运行 OCR，因此不产生字符准确率、字段准确率或模型准确率。

真实引擎测试回答“某个确定版本的 OCR 引擎在固定数据集上的识别效果”。只有同时保存以下信息，结果才可复现：

- 引擎名称、版本和模型版本；
- 运行参数、语言配置和预处理方式；
- 操作系统、CPU/GPU 及关键依赖版本；
- 原始图片或 PDF、逐字真值和未经人工改写的引擎输出；
- 统计脚本、归一化规则、样本数及失败样本。

## 建议指标

- 字符错误率 CER：编辑距离除以真值字符数；
- 关键字段完全匹配率：课程名、权重、日期、地点等逐字段统计；
- 可用解析率：能形成合法 `ParseResult` 的样本数除以总样本数；
- 人工确认率：状态为需要人工确认的样本数除以总样本数。

空格、全角半角和行尾标点是否归一化，必须在统计前固定。不能只展示成功样本，也不能把人工修正后的文字当作引擎原始输出。

## 当前范围

本仓库验证的是夹具转换管线、EasyOCR 适配器和记录式 OCR JSON 的接入格式。默认测试不下载模型，也没有测量字符准确率或字段准确率。`samples/outputs/easyocr-real-run.json` 记录了一次真实引擎尝试；当前运行失败，`accuracy` 保持 `null`，不能作为准确率结果。JSON 中的置信度只是外部引擎输出的字段，不等于本项目测得的准确率。
